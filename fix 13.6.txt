1. HARD TIMEOUT IS BYPASSED WITH REAL TASKS

ToolRegistry attempts to pickle TaskCapsule. TaskCapsule contains locks and is not serializable, so process isolation fails and execution silently falls back to ThreadPoolExecutor. The timeout returns, but the thread continues and performs delayed side effects.

Fix:
- Never serialize or send TaskCapsule to a child process.
- Create a small serializable WorkerRequest containing only task ID, tool name, validated arguments, deadline and cancellation metadata.
- Return ToolResult plus resource/undo metadata to the parent; the parent updates TaskCapsule and the ledger.
- State-changing/external tools must never fall back to threads when process isolation fails. Return a fail-closed execution error.
- On timeout or STOP, terminate the worker and its complete process tree, wait for termination, then close every handle.

Required test: execute a non-cooperative delayed side-effect tool with a real TaskCapsule. After timeout and an additional wait, the side effect must not exist. Repeat 20 times and prove no worker/thread/handle growth.

2. UI GROUNDING IS NOT ENFORCED

snapshot_id and target_ref remain optional. target_ref is never resolved. Invented references and ungrounded name-based clicks succeed.

Fix:
- Make snapshot_id and target_ref mandatory for click/type actions.
- Store HWND, PID, 64-bit process creation time, window class/title/rectangle/DPI and element geometry in ScreenSnapshot.
- inspect_active_window must return target_ref containing the exact stored element_id.
- Resolve snapshot_id and element_id from the task’s SnapshotRegistry.
- Immediately before interaction, re-read and compare window identity, foreground state, DPI, geometry and element bounds.
- Unknown, expired, moved, ambiguous or mismatched references must fail.
- Remove name/label fallback and verify_noop from state-changing UI actions.
- Add real action-specific postconditions.

Required tests: invented/expired references, changed HWND/PID/creation-time/geometry/DPI and ungrounded clicks must all fail without performing input.

3. OPEN_APP IS NOT ALLOWLISTED

The validator rejects some dangerous names, but execution still runs shutil.which(app) or the supplied path.

Fix:
- Permit only built-in aliases and explicitly configured owner-approved aliases.
- Delete arbitrary path/unknown executable fallback.
- Reject unknown absolute paths, shells, interpreters, script hosts, reg.exe and schtasks.exe.
- Make Job Object assignment mandatory for PLUMA-created processes. If containment fails, terminate the process and return failure.
- Successful persistent apps may survive task completion, but STOP must terminate the owned process tree using verified PID plus creation timestamp.

4. IPC AUTHENTICATION IS DISABLED AND THE CUSTOM HANDSHAKE IS INVALID

ResidentCore constructs IpcServer with require_auth=False. The server also sends the value used as the HMAC key to the client, so it is not a secret.

Fix:
- Make authenticated IPC the production default and explicitly enable it in ResidentCore and official clients.
- Use multiprocessing Listener/Client authkey with a persistent random secret, or challenge-response using a separate stored secret that is never transmitted.
- Store the secret with verified current-user-only ACL on Windows and mode 0600 on Linux.
- If secret persistence or ACL verification fails, refuse to start IPC.
- Enforce bounded connection, read and write deadlines, bounded client concurrency and message sizes. No insecure fallback.

Required test: unauthenticated and wrong-secret clients must be rejected by the actual ResidentCore server.

5. ELEVATION STILL ACCEPTS ARBITRARY SCRIPT EXECUTION

- Do not interpolate user values into PowerShell command strings.
- Use structured argument passing, -PassThru, wait for the child and propagate its real exit code.
- Apply timeout, STOP and process-tree containment to elevated children.

6. ROLLBACK CONSUMPTION MUST BE ATOMIC

Perform verified rollback, consume the undo record and write the rollback result in one SQLite transaction. If any part fails, roll back the transaction, report failure and leave the undo record available. Never report success when mark_undo_consumed fails.
