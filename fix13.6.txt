ROOT CAUSE: ToolRegistry’s global isolated worker removes the real TaskCapsule context. It also kills only the worker process—not its descendants.

1. REBUILD TOOL EXECUTION AND STOP

Replace _GLOBAL_WORKER_POOL with a per-task execution controller keyed by task_id.

Requirements:
- Use multiprocessing.get_context("spawn") consistently; do not use global multiprocessing.Process/Pipe directly.
- Create a fresh killable worker for each state-changing ToolCall, or a strictly task-owned worker.
- Assign the worker and every descendant to the TaskCapsule’s kill-on-close Windows Job Object.
- Store the worker process, pipe and Job handle in the parent execution controller.
- STOP must locate the active worker by task_id, terminate its complete Job Object, join it, close handles, and only then start rollback.
- Timeout must perform the identical termination sequence.
- Never fall back to a thread for state-changing or external tools.
- Remove `except TypeError: executor(args)`; an internal TypeError must not cause the operation to execute twice.

- After the worker returns, reject success if the real capsule’s cancellation latch is set.

Acceptance test: a worker spawns a child that waits and writes a file. Both timeout and STOP must prevent the file from appearing. Repeat 20 times and prove zero workers, children, threads or handles remain.

2. PRESERVE PARENT-OWNED APPLICATION JOB HANDLES

WorkerTaskContext currently removes `persistent_job`, so STOP cannot terminate applications launched through ToolRegistry.

Do not serialize OS handles.

Implement open_app through a parent-owned application launch controller:
- Resolve only an approved application alias.
- Create the process suspended.
- Create a parent-owned WindowsJobObject(kill_on_close=False).
- Assign the suspended process to it, record PID plus 64-bit creation time, then resume.
- On containment failure, terminate the process and fail.
- Store the real Job handle in TaskCapsule.owned_resources.
- Successful completion closes handles without terminating the application.
- STOP verifies PID identity, calls TerminateJobObject once, waits for exit and closes every handle.
