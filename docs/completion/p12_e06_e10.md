# P12 E-06 through E-10: targeted OCR safety and STOP ownership (E65)

## Outcome

The requested E-06 through E-10 gates pass on `p12-preparation`. P12 remains
open because its 16 screen-control catalog entries and the separate locked OCR
engine configuration are still outstanding. This evidence closes only these
five acceptance rows.

## Changes and evidence

- **E-06 — scoped capture:** `WindowCapture.capture_region` now refuses an
  invalid supplied HWND and any crop outside that window. With an HWND, it
  captures only that target window and crops the bitmap in memory. It no longer
  uses desktop BitBlt for a window-relative OCR region, which could include an
  unrelated window covering the same screen coordinates. Unit tests prove the
  invalid/out-of-bounds refusals. The owned Win32 fixture confirms that OCR
  receives two 160x100 BMP crops from its requested window-relative region.
- **E-07 — target transition readback:** the OCR click refreshes active HWND,
  PID and process creation identity, geometry, DPI, and supplied snapshot
  freshness before coordinate dispatch. Snapshot metadata is resolved in the
  parent and carried into the owned worker without `image_ref`. After input,
  OCR verification requires the unique matched text to disappear or move from
  its original bounds. A count change caused by unrelated words does not pass.
  OCR errors are reported as errors rather than empty text. Unit cases cover a
  confirmed transition, unchanged target, unrelated added text and failed
  post-recognition.
- **E-08 — unsupported textless target:** the owned blank Win32 fixture has no
  actionable UIA controls. Empty OCR returns `OCR_NO_MATCH`, and the input
  adapter is not called. No coordinate is guessed.
- **E-09 — screenshot privacy:** target images and crops remain in memory.
  The OCR path never uses the explicit temporary-file capture API. Tests check
  that tool output contains no image bytes or image reference and that no
  capture file is created.
- **E-10 — STOP during OCR:** `click_ocr_text` now requires an owned process
  worker. The same cancellation token reaches OCR and is checked before any
  later click or readback. A Windows test runs the registered tool with an
  intentionally uncooperative OCR fixture, latches STOP through
  `TaskSupervisor`, and verifies `TASK_CANCELLED`, worker absence, and no click
  marker. OCR backends that block synchronously are bounded by termination of
  this task-owned worker.

The native region and textless-window tests use only windows created by their
fixture. OCR recognition and input are injected to make the target-transition
and refusal assertions deterministic; the E-06 crop itself uses the real
Windows HWND capture path. No pre-existing window is activated or modified.
This does not measure OCR model accuracy or certify the locked PaddleOCR/ONNX
configuration.
