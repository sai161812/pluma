# P12 E-01/E-02: native semantic UIA evidence (E62)

## Outcome

The first bounded P12 task passes for a standard native Win32 fixture. The registered `inspect_active_window` tool returned semantic Submit and status controls through UIA. The registered `click_element` tool selected UIA, confirmed Submit was enabled before dispatch, invoked it, and read back the expected disabled state. An independent UIA read returned the disabled Submit control and the fixture's updated `Submitted` status. The test's capture and OCR guards were not accessed.

P12 remains open. This evidence does not cover WPF-specific providers, E-03 through E-10, or the remaining 16 section-21 screen-control names.

## Implementation

- `pluma/tools/registry.py` now passes the snapshot-resolved target through a per-call overlay on the owned-thread executor path without mutating the shared task context. The native test previously reached the registered click tool without that grounding and was refused.
- `pluma/adapters/win32.py` reads `GetWindowRect` while temporarily matching the target window's DPI-awareness context and restores the caller's context. The native test exposed inconsistent virtualized rectangles between worker threads; grounded input now compares coordinates in the same target space.
- `pluma/tools/ui.py` requires an expected enabled state for a semantic click, reads the current state first, refuses if the expected state is already present, and verifies the state transition after invocation. Missing or unchanged postconditions are refused before dispatch.
- `pluma/verify/screen.py` independently reads the control's enabled state through UIA and compares it with the expected value.
- `tests/fixtures/uia_semantic_target.py` creates an owned, non-activating Win32 window with a Submit button and a status label. The Submit action disables the button and changes the label to Submitted. The native test closes only this fixture and verifies process exit.

The acceptance test binds production active-window context to the exact owned fixture HWND because the current test session has no usable foreground window. It still obtains the HWND, PID, process creation time, geometry and DPI from Win32 and uses the real Windows UIA provider for discovery, invocation and readback. It does not claim foreground/focus acceptance, activate a pre-existing window, or persist a screenshot.
